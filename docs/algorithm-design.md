# M2 算法核心设计：先天起卦「分总 / 漏斗」结构

> 项目：meihua-xiantian-qigua ｜ 状态：规则已核对、**M2 核心已实现**（`node tests/run-tests.js` 108 项全过）；M3 页面待建 ｜ 范围：**仅《梅花易数》先天起卦法**

## 1. 决策记录

| 议题 | 决定 |
|---|---|
| 范围 | 只做先天起卦法（以数起卦）；**后天端法（象/方位起卦）本期排除**，仅在设计上预留适配点 |
| 结构 | 分总/漏斗：叶子(取数) → 中层(配数规则，可配置) → 根(唯一成卦核) |
| 首批规则 | ① 时间起卦法 ② 一数起卦法 ③ 二数起卦法 ④ 三数起卦法 ⑤ 多数起卦法 |
| 缺动爻出口 | 默认**自动补时辰数求动爻**（配置可关，可切换"静卦提示"）；一数起卦法即借时辰补足 |
| 口径 | 依《梅花易数》通行本口径（年支序数等）；除八/除六余 0 记 8（坤）/ 6（上爻） |

> **术语约定（现代称呼）**：本项目统一用现代方法名——**时间起卦法**（以农历年/月/日/时辰四要素取数，即观梅占、牡丹占等古例所用的同一方法）、**一数起卦法**、**二数起卦法**、**三数起卦法**、**多数起卦法**。古例名（观梅占、牡丹占…）不再作为方法名使用，仅作校验案例的出处标注，写法如"时间起卦法 · 观梅占例"。
> **对外入口（UI/调用层）只分两类**：① **时间起卦**（= time 规则）；② **数字起卦**（= 数字序列入口，内部按个数自动分派：1 个 → 一数起卦法（借时辰）、2 个 → 二数起卦法、3 个 → 三数起卦法、≥4 个 → 多数起卦法）。5 条 rule 记录只存在于规则层，不暴露给用户。
> **规则核对**：各方法的槽位规则与演算示例见 `docs/rules-demo.md`（用户核对通过后才锁进 `rules.json`）。

## 2. 领域模型：一个管道、三个槽位

先天法任何方式最终都映射为三个槽位（槽位存**原始整数**，取模在成卦核统一做）：

```
上卦槽  = 规则选取的一组数          → ÷8 取余（0→8）→ 上卦
下卦槽  = 规则选取的一组数          → ÷8 取余（0→8）→ 下卦
动爻槽  = 规则选取的总数（可空）    → ÷6 取余（0→6）→ 动爻
```

各方式差异只在"槽位公式"（取哪些原始数、是否求和、是否加时辰）。进一步归纳为**三种槽位分组模式**：

| 模式 | 方法 | 槽位分组 |
|---|---|---|
| P1 语义分组 | 时间起卦法 | 上=前 3 项和（年+月+日），下/动=全 4 项和（+时辰）——"下卦与动爻同源" |
| P2 对半分组 | 二数/三数/多数起卦法 | 按序对半分：上=前 ⌊k/2⌋ 项和，下=后 ⌈k/2⌉ 项和（k=2→1\|1，k=3→1\|2，k=5→2\|3），动=全和 |
| P3 单数借时 | 一数起卦法 | 只给一数，下卦/动爻借**当下时辰**补足（上=n，下=n+时辰，动=n+时辰） |

> P2 是书内"字占分组表"（二字、三字、四字以上均分）在纯数字上的直接推广；P1 因年月日/时辰语义不对等而保留独立公式；P3 是"数据不足"时的补足特例。三者之上只挂一个成卦核。

### 2.1 爻序与数组索引约定（编码铁律 ⚠️）

变卦（之卦）是否算对，全看这条映射是否一致，任何环节都不得混用：

- **全卦六爻数组 `hexLines[0..5]` 一律自下而上存储**：`[0] = 初爻（最下）`、`[5] = 上爻（最上）`。与 M1 数据一致（`trigrams.json` 的 `lines` 自下而上、`zhouyi-classic.json` 的 `yaoCi` 按初→上排列）。
- **动爻位 `dongYao ∈ 1..6`**（1=初爻 … 6=上爻，自下而上）→ **数组下标 = `dongYao − 1`**。
- **变卦** = 翻转 `hexLines[dongYao − 1]`（0↔1），其余五爻不动。
- **显示层倒序只是渲染**：爻画若从上往下画（上爻在顶），仅遍历时倒序，**禁止回写算法数组**。

| 爻位称谓 | 自下而上位 p | 本约定数组下标 | 示例（观梅占动初爻） |
|---|---|---|---|
| 初爻 | 1 | 0 | 翻转 lines[0] |
| 二爻 | 2 | 1 | — |
| 三爻 | 3 | 2 | — |
| 四爻 | 4 | 3 | — |
| 五爻 | 5 | 4 | — |
| 上爻 | 6 | 5 | — |

> 备选备忘：若未来改用"自上而下"存储（`[0]=上爻`），映射必须同步为 `下标 = 6 − dongYao`，且全项目唯一；本项目固定使用**自下而上**方案。

## 3. 分层架构

```
叶子层（取数适配器 = 对外两类入口）
     时间起卦入口      → 产出 {yearBranch, month, day, hourBranch}（农历要素）
     数字起卦入口      → 产出 {numbers:[…]}，个数 1/2/3/≥4 自动分派：
                        1 个 → one-number（借当前时辰）；2 → two-numbers；
                        3 → three-numbers；≥4 → many-numbers
     （未来：字数/声数/物数/笔画/尺寸 = 归一化为数字序列喂入数字起卦入口，接口相同）
        ↓ 原始数串
中层（配数规则，数据驱动）  rules.json 每条规则声明：inputs、槽位公式（分组边界）、动爻来源、
                           是否需要借时辰补齐
        ↓ 槽位原始数 {upperRaw, lowerRaw, moveRaw|null}
根（唯一成卦核 cast）       mod8/mod6(0→8/6) → 查 64 卦 → 本卦
                           → (若有动爻) 之卦 / 互卦 / 体用 / 五行关系
        ↓
盘对象（纯数据，供 UI 渲染）
```

要点：
- **成卦核唯一**：`cast({upperRaw, lowerRaw, moveRaw})`，不感知任何具体起卦方式；
- **规则即数据**：新增起卦方式 = `rules.json` 加一条 + （必要时）加一个取数器；不动成卦核；
- **补齐策略进规则**：`move` 槽为空且该方式要求动爻时，按 `moveFallback` 处理（默认补时辰序数）；
- 体用/变卦等派生逻辑全部收敛在核内，与方式无关。

## 4. rules.json 规则 schema（首批 5 条）

```jsonc
// 示意：字段以 M2 实现为准，expr 为最小表达式（字段名/求和/取模在核内解析）
{
  "rules": [
    {
      "id": "time", "name": "时间起卦法",
      "inputs": ["yearBranch", "month", "day", "hourBranch"],
      "upper": { "expr": "yearBranch+month+day" },
      "lower": { "expr": "yearBranch+month+day+hourBranch" },
      "move":  { "expr": "yearBranch+month+day+hourBranch" },
      "fallback": null
    },
    {
      "id": "one-number", "name": "一数起卦法（借时辰补足）",
      "inputs": ["n"],
      "autoHour": true,                    // 自动取当前时辰序数 hourBranch
      "upper": { "expr": "n" },
      "lower": { "expr": "n+hourBranch" },
      "move":  { "expr": "n+hourBranch" },
      "fallback": null
    },
    {
      "id": "split-numbers", "name": "数字分组起卦法（二/三/多数共用对半分组通式）",
      "inputs": ["numbers"],               // 数组，长度 k ≥ 2
      "grouping": "split-half",            // 上=前 ⌊k/2⌋ 项和；下=后 ⌈k/2⌉ 项和；动=全和
      "upper": { "split": "first-half" },
      "lower": { "split": "rest-half" },
      "move":  { "expr": "sum(numbers)" },
      "fallback": null
    }
  ],
  "presets": [                            // 同一通式下的常用入口（UI 文案/表单不同，公式同源）
    { "id": "two-numbers",  "name": "二数起卦法",  "presetOf": "split-numbers", "expect": 2 },
    { "id": "three-numbers", "name": "三数起卦法", "presetOf": "split-numbers", "expect": 3,
      "variant": { "upper": { "expr": "n1+n2" }, "lower": { "expr": "n3" } } },  // 备选口径 2|1
    { "id": "many-numbers",  "name": "多数起卦法", "presetOf": "split-numbers", "expect": ">=4" }
  ],
  "defaultFallback": { "type": "addHourBranch", "moveExpr": "sum(rawUpper+rawLower)+hourBranch" }
}
```

> 说明：
> - **三数起卦法默认 1|2**（上=第1数、下=第2+3数之和），依据书·三字占"姓上名下"口径；备选口径 2|1（上=前两和、下=末数）以 `variant` 承载，待用户确认（见 `docs/rules-demo.md` §5-A2）。
> - 若需把"对半分组"改为其它边界（如时间要素式前3|全4），仅改 `grouping/expr`，成卦核不受影响。
